1. 배경 및 필요성

2025년 개발자 채용 시장은 수요-공급 불일치가 두드러집니다. 사람인·점핏의 『2025 상반기 개발자 채용 리포트』(공고 10만여 건, 입사지원 260만여 건 분석)에 따르면 기업 공고는 5~10년차 경력직(39.7%)에 몰려 있고 신입 공고 비중은 0.8%에 불과한 반면, 입사지원은 신입이 29.5%로 가장 많아 신입 개발자의 채용 미스매치가 구조적입니다 [2].

자소설닷컴의 2025 상반기 트렌드 조사에서는 채용공고 조회수 7,224만 회(+15.7%), 자기소개서 작성 수 127만 건(+10.5%)으로 지원 활동량 자체가 증가했습니다 [3]. 즉 지원자는 "더 많이" 쓰고 있지만, CS 직무 연관성 기준으로 공고를 필터링하고 자소서·면접을 체계적으로 준비할 도구의 필요성이 커지고 있습니다.

JobFilter는 이 문제를 겨냥한 컴퓨터공학과 특화 채용 포털로, ① CS 직무 키워드 기반 공고 자동 분류·매칭, ② 규칙 기반 자소서 코칭("자소서는 내가 직접" — 생성형 AI 대신 문장 프레임·루브릭 제공), ③ 결정론적 모의면접(표준 문항 풀 + 4대 구조 체크리스트)을 핵심 기능으로 설계되었습니다.

2. 설계 및 제작 도구

디자인 시스템 (DESIGN.md)

  • Corporate/Modern SaaS 언어 — Linear·GitHub Insights 계열 고밀도 대시보드
  • 색상: Deep Portal Navy(#14396B) · Match Green · Amber · Alert Red · Info Blue
  • 타이포: Pretendard/Inter + JetBrains Mono(지표·ID·D-day 표기)
  • 240px 고정 사이드바 + 56px 상단 바, 8pt 그리드 스페이싱

Google Stitch 활용

  • Stitch는 Google Labs의 AI UI 생성 도구 — 자연어 프롬프트로 고충실도 화면+HTML/CSS 생성[1]
  • DESIGN.md를 디자인 시스템으로 업로드해 9개 화면에 일관된 테마 적용
  • 화면당 구조·콘텐츠 프롬프트 입력(stitch-prompts.md), 색상 지시는 시스템이 처리

3. 구현 — 공통 인터랙션 레이어

생성된 HTML을 재작성하지 않고 app.js 하나로 전 화면의 동작을 구현하는 프로그레시브 인핸스먼트 방식을 채택했습니다. 프레임워크·빌드 없이 정적 호스팅만으로 동작합니다.

① 페이지 디스패치

URL에서 화면 식별 → 화면별 init 함수 실행. 공통 내비·제네릭 규칙이 먼저 적용되고 화면별 로직이 덧붙음

② 텍스트 규칙 위임

문서 레벨 클릭 위임으로 버튼/링크 텍스트·아이콘을 규칙에 매핑 — 핸들러 없는 컨트롤에도 실동작 또는 피드백 부여

③ 브라우저 API 활용

FileReader(CSV 파싱), Blob 다운로드, Clipboard, localStorage(버전 스냅샷), HTML5 Drag&Drop, setInterval 타이머

4. 화면별 구현 기능

화면구현된 인터랙션
S-01 대시보드사이드바 내비·검색창(Enter→S-02)·북마크 토글·업데이트 버튼·알림 피드백
S-02 공고 목록실시간 검색 필터·정렬 4종(매칭/마감/최신/스크랩)·필터 칩·초기화·페이지 크기+페이지네이션·최대 3개 비교 모달·스크랩
S-03 공고 상세스크랩 토글·공유(클립보드)·칸반 등록·원문 링크 피드백
S-04 자소서 코칭문항 탭별 본문 분리(localStorage)·툴바 포맷팅(굵게/기울임/목록/코드)·버전 스냅샷 저장·이력 패널 복원·PDF보내기·키워드 히트맵
S-05 지원 칸반카드 드래그앤드롭 6단계·건수 배지 갱신·신규 등록 모달(D-day 자동계산)·드로어 상태 변경·마감순 정렬·긴급 필터·삭제
S-06 기업 공고상태 탭 필터·카운트 재계산·검색/정렬·행별 마감/수정/검토요청/재등록/사유확인·단건 등록 모달·CSV 실파싱 일괄 미리보기·템플릿 다운로드
S-07 관리자승인/반려/일괄처리·키워드 사전 CRUD·업로드 로그·동기화 (인라인 스크립트 유지)
S-08 모바일검색 필터·정렬·스크랩 전용 보기·더 불러오기(카드 실제 추가)·하단 탭 바
S-09 모의면접직군 칩 선택·문항 풀 랜덤 교체·다음 문항 진행도·90초 카운트다운(일시정지/리셋)·답변 글자수·분량 판정·CSV보내기

5. 화면 갤러리

※ 썸네일은 Stitch 프로젝트 원본 스크린샷. 클릭하면 원본 크기로 열립니다.

6. 검증 결과

Playwright로 로컬 및 라이브 환경에서 전수 검증했습니다. 각 화면의 모든 <a>/<button>에 대해 핸들러·위임 규칙 바인딩을 정적 감사하고, 핵심 동작은 실제 클릭/입력으로 확인했습니다.

검증 항목방법결과
콘솔 에러9개 화면 로드 시 콘솔 감시0건
무반응 컨트롤전체 a/button 바인딩 감사0건 (위임 규칙 커버)
검색 필터S-02 "spring" 입력6→3건 정확히 필터링

8. 결론 및 한계

결론: Stitch 생성 화면의 디자인을 손상하지 않으면서 공통 스크립트 레이어만으로 60개 이상의 컨트롤을 실동작화했고, 전수 감사에서 무반응 요소 0건·콘솔 에러 0건을 달성했습니다. 규칙 기반 설계 철학(환각 없는 템플릿/루브릭)은 S-04·S-09 구현 방식과 일관되게 유지됩니다.

한계: 정적 프로토타입이므로 데이터는 페이지 새로고침 시 초기화됩니다(버전 스냅샷만 localStorage 보존). 실제 서비스화 시 백엔드 API·인증·DB가 필요하며, 음성 녹음(STT)과 엑셀(.xlsx) 파싱은 브라우저 제약상 안내 메시지로 대체되었습니다.
